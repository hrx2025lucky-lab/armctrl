# armctrl — 机械臂运动规划与柔顺控制栈（MuJoCo）

工业与协作机械臂运动控制的实现与验证项目。以 Franka Panda（7 自由度冗余臂）为对象，
在 MuJoCo 中实现从运动学、规划到力矩级柔顺控制的完整链路，每个模块都配可复现的
定量验证实验。

## 环境

依赖：`mujoco 3.12` · `pinocchio 4.1` · `numpy` · `scipy` · `matplotlib` · `toppra`

机器人模型来自 [mujoco_menagerie](https://github.com/google-deepmind/mujoco_menagerie)
的 `franka_emika_panda/panda.xml`。该资产仓库独立分发，需自行获取：

git clone https://github.com/google-deepmind/mujoco_menagerie.git

## 已验证结果

### 末端执行器：TCP 与平行夹爪

**TCP 缺省就是指尖抓取中心，不是法兰。** `make_panda()` 的 `tcp_offset` 为
`[0, 0, 0.1029] m`（hand 系），由模型几何独立推出：

    finger body 原点        hand + 0.0584 m·ẑ         (panda.xml: left_finger pos)
    指尖夹持垫 z 向包络     [0.0360, 0.0530] m        (5 个 fingertip_pad 碰撞盒的并集)
    夹持垫中心              0.0445 m
    TCP = 0.0584 + 0.0445 = 0.1029 m                 (Franka 标称 0.1034，差 0.5 mm)

`fk()` / `jacobian()` / `task_space_inertia()` 全部作用在 TCP 上；点雅可比用
`mj_jac(point, body)`，满足杠杆项恒等式（数值验证到 1e-16）：

    J_tcp,lin = J_flange,lin − [R·o]× J_rot,      J_tcp,rot = J_flange,rot

由此可推出两个容易搞错的结论：令 `T = [[I, −S],[0, I]]`，则 `J_tcp = T·J_flange`，
`det(T) = 1`，所以 **Yoshikawa 可操作度对 TCP 偏置不变**（实测两者差 9e-17）；
但 `T` 不是正交阵，**条件数和任务空间惯量都会变**（Q_HOME 处条件数 8.7606 → 8.9101）。

需要法兰位姿时用 `flange_pose()`；需要旧口径时用 `make_panda(tcp="flange")`。

| 量 | 法兰口径 | 指尖 TCP 口径 |
|---|---|---|
| 标称可达半径 `char_length` | 0.857704 m | 0.946669 m |
| 阻尼阈值 `sigma0_pos` | 0.025468 | 0.030707 |
| 阻尼阈值 `sigma0_pose` | 0.008934 | 0.008869 |

#### 夹爪：出厂伺服夹不住东西

Panda 的夹爪是**腱传动位置伺服**（`split` 腱，两指系数各 0.5，`actuator8`），
不是力矩电机，因此 `ArmModel` 的力矩化**不作用在它身上**。张口宽度
`width = q1 + q2 ∈ [0, 0.08] m`，`ctrl ∈ [0, 255]`，映射由伺服不动点
`kp(len_target − len) = 0` 解出，不硬编码。

腱力由 `f = kp·(过闭合量)` 给出，出厂 `kp = 100 N/m`、单指行程 0.04 m
⇒ **最大腱力只有 4 N**，与 `forcerange` 无关。实测夹持一个 24 mm 方块：

| 指令夹持力 | 伺服 kp (N/m) | 腱力 (N) | 单指法向力 (N) | 稳态张口 (m) |
|---|---|---|---|---|
| 出厂（只抬 forcerange） | 100 | 1.20 | 0.60 | 0.0240 |
| 10 N | 2500 | 9.68 | 4.84 | 0.0237 |
| 20 N | 5000 | 18.82 | 9.41 | 0.0235 |
| 40 N | 10000 | 36.04 | 18.02 | 0.0232 |
| 60 N | 15000 | 52.48 | 26.24 | 0.0230 |

`set_grip_force(F, squeeze)` 取 `kp = F/squeeze` 并把 `forcerange` 封顶在 `F`，
于是过闭合量 ≥ squeeze 时腱力精确等于 F。单指法向力 ≈ 腱力/2（split 腱系数）。

**夹持必须两段式**（`close_and_grip`）：先用出厂软伺服贴近到 `工件宽度 + 4 mm`，
再抬 kp 施加夹持力。一步到位用 15000 N/m 从全张开砸下去，实测张口会冲到
**−0.0476 m**（穿过工件并冲破关节限位），工件被打飞。松开时同理要先
`restore_factory_servo()`（`release()` 已包含），否则高刚度弹开会把工件打出去。

#### 运动平滑性：控制器没问题，缺的是轨迹规划

夹爪 demo 第一版看起来"又快又顿"。根因不是控制器，而是**根本没有参考轨迹**：
`p_des` 一次性跳到终点，笛卡尔阻抗环就退化成一个二阶系统的阶跃响应，
只能以闭环带宽允许的最快速度冲过去。

控制器自始至终是同一个：`τ = Jᵀ[K(x_d−x) + D(ẋ_d−ẋ)] + h(q,q̇)`，
K = 1500 N/m、ζ = 1（`D = 2ζ√(ΛK)`，随构型自适应）。只换喂给它的 `x_d(t)`：

| 参考 | 峰值速度 (m/s) | 峰值加速 (m/s²) | 峰值 jerk (m/s³) | 90% 行程 | 总时长 |
|---|---|---|---|---|---|
| 阶跃目标 | 0.4787 | 24.79 | **3098.0** | 0.296 s | 5.00 s |
| S 曲线 + 速度前馈 | 0.1036 | 0.44 | **8.0** | 0.978 s | 1.65 s |

80 mm 提升动作：**jerk 降低 385 倍，加速度降低 56 倍**，终点误差不变（0.98 → 0.97 mm）。
S 曲线用的就是本项目 `planning/trajectory.py` 的 `CartesianLine`
（七段式 S 曲线时间律 + 四元数 slerp），并把 `ẋ_d` 作为前馈送进阻抗律。

夹爪自己也一样：`command_width()` 是阶跃指令，实测张口在 **0.246 s** 内走完 90%
行程（峰值闭合速度 0.34 m/s）然后干等。改成 `move_width()`（同样是 S 曲线）后
峰值闭合速度降到 **0.029 m/s**，行程均匀铺满整段。夹持力也从"kp 100→15000 一次跳变"
改成 `apply_grip_force()` 斜坡加载。

平滑化还带来两个副产品：提起阶段的滑移从 **4.5 mm 降到 2.1 mm**；平滑闭合会把
偏置的工件**扫回中心**（偏 30 mm 的方块残余 < 2 mm，已作为用例固定下来）。

全序列实测：时长 11.4 s，TCP 峰值速度 0.1038 m/s（限 0.10）、峰值加速 0.443 m/s²
（限 0.40）、**处于运动状态的时间占比 50%**（旧版阶跃只有约 6%）。残余 jerk 峰值
69 m/s³ 全部出现在**分段交界**（t = 4.32 / 6.17 / 7.78 s），那些时刻 TCP 速度只有
0.0002 m/s，即手臂已经停住——因为每段都是 rest-to-rest，没有做过点速度衔接。

Pick & place 实测（`demos/demo_gripper.py`，24 mm/0.15 kg 方块，60 N 夹持）：

| 阶段 | 方块 y (m) | 方块 z (m) | 张口 (m) | 单指法向力 (N) |
|---|---|---|---|---|
| 初始（张开） | -0.0000 | 0.4130 | 0.0800 | 0.00 |
| 夹持 | -0.0000 | 0.4129 | 0.0230 | 26.28 |
| 提起 +80 mm | -0.0000 | 0.4908 | 0.0230 | 26.24 |
| 平移 +100 mm | 0.1000 | 0.4896 | 0.0230 | 26.24 |
| 下放 | 0.1000 | 0.4135 | 0.0230 | 26.24 |
| 松开并撤离 | 0.1000 | 0.4129 | 0.0800 | 0.00 |

净位移 Δy = +100.0 mm、Δz = −0.1 mm；提起阶段工件上升 77.9 mm（指令 80 mm），
滑移 2.1 mm。

### 姿态误差契约：OrientationErrorTracker / reset（阶段 2）

θ = π 时 R(a, π) = 2aaᵀ − I = R(−a, π)，主值 SO(3) 对数**两值**，任何单值连续选择
都不存在（拓扑切割，不是公式 bug）。因此凡是按拍调用姿态误差的控制器，都必须走
`OrientationErrorTracker`，并遵守下面的契约：

**两级状态严格分离**

| 级别 | 输出 | 保证 |
|---|---|---|
| 1. 连续 lift（`tracker.lift()`） | `e_lift` | `exp(skew(e_lift))` **恒等于** `R_des·R_curᵀ`；‖e_lift‖ ∈ [0, 2π)，允许超过 π，这正是跨切割面连续所必需的 |
| 2. 控制命令（`tracker.update()`） | `command` | `= 限幅(限速(e_lift))`，两者**缺省全部关闭**；一旦开启，command **不再是 R_err 的精确对数**，它是控制命令饱和的结果 |

限速/限幅的结果**永远不会**写回第 1 级的分支历史。这是与上一版最大的差别：上一版把
限幅后的值写回 `_prev`，导致 ‖ω_alt‖ > π 被 `max_norm = π` 缩放后已不再代表同一旋转。

**reset 契约**

- 首次调用 / `reset()` 之后没有历史，`e_lift` 取主值（格点 k = 0），因此 `reset()` 后
  重放同一帧必然复现无状态 `so3_log` 的结果。
- **episode 切换时调用方必须调用 `reset()`**，否则新 episode 的第一拍会继续沿用上一个
  episode 的分支历史。`CartesianImpedanceController.reset()` 与
  `HybridForcePositionController.reset()` 都已暴露（后者同时清空力控积分器）。
- 单帧输入相同但历史不同时，`e_lift` 可能落在两个等价格点之一，但**两者都精确表示同一个
  `R_err`**；不会返回被限速/限幅的值。

**限速必须显式给 dt**：`max_rate` 缺省为 `None`（关闭）。开启时必须提供真实 dt
（构造参数或 `update(dt=...)` 逐拍传入），否则抛 `ValueError`——不存在隐藏的 0.002 s。
缺省关闭的原因是实测：上一版 `max_rate = 8 rad/s`、`dt = 0.002` 给出单拍上限 0.016 rad，
5–20 rad/s 的正常姿态参考会被限速，产生被隐藏的跟踪滞后。

## 设计要点

**位置伺服 → 力矩电机**：Menagerie 的 Panda 默认使用位置伺服执行器
（`gainprm=kp, biasprm=[0,−kp,−kd]`），`d.ctrl` 是位置目标。做力矩级控制必须
在加载后就地把执行器改为直通电机，否则内置 PD 会与外层控制律打架 ——
这是最初实验中稳态偏移符号和量级全错的原因。

**阻尼必须随构型自适应**：任务空间惯量 Λ(q) = (J M⁻¹ Jᵀ)⁻¹ 随构型变化很大，
用固定的 2ζ√K 会在惯量大的方向欠阻尼。用对称平方根 Λ^{1/2} 保证 D 正定。

**摩擦补偿不补满**：拖动示教中库仑摩擦补偿系数取 0.8 而非 1.0，并设速度死区。
补过头会产生自激爬行（limit cycle）。

## 回归矩阵与参数辨识（`identification/regressor.py`）

动力学对惯性参数线性：`M(q)q̈ + C(q,q̇)q̇ + g(q) + Fv q̇ + Fc sgn(q̇) = Y(q,q̇,q̈)·π`

参数向量 91 维 = 连杆惯性参数 70 + 转子惯量 7 + 粘性摩擦 7 + 库仑摩擦 7。
SVD 求基参数集：**91 → 62 可辨识**（29 个参数对关节力矩无影响或只以固定组合出现）。

### Slotine-Li 回归矩阵的构造

自适应控制需要的是 `Y_SL·π = M(q)q̈ᵣ + C(q,q̇)q̇ᵣ + g(q)`，科氏项混合了实测速度 q̇
与参考速度 q̇ᵣ，无法直接调用标准回归矩阵，7 自由度手推也不现实。

利用 Christoffel 形式下 `C(q,a)b = C(q,b)a` 的对称性与极化恒等式

```
C(q,q̇)q̇ᵣ = ½[ C(q,q̇+q̇ᵣ)(q̇+q̇ᵣ) − C(q,q̇)q̇ − C(q,q̇ᵣ)q̇ᵣ ]
```

得到只需 5 次标准回归矩阵调用的精确构造：

```
Y_SL = A + ½(B₊ − B₁ − B₂) + ½G
A = Y(q,0,q̈ᵣ)   B₊ = Y(q,q̇+q̇ᵣ,0)   B₁ = Y(q,q̇,0)   B₂ = Y(q,q̇ᵣ,0)   G = Y(q,0,0)
```

验证：`Y·π` 与 RNEA、`Y_SL·π` 与 `M q̈ᵣ + C q̇ᵣ + g + Fv q̇ᵣ + Fc sgn(q̇)`
在随机构型下最大偏差 **~1e-14**（机器精度）。

单元测试：用真值初始化并冻结自适应（Γ=0）时，MBAC 稳态误差 1.06 mrad，
与精确模型 CTC 完全一致，证明控制律与回归矩阵实现正确。

## 调试记录

1. **位置伺服 vs 力矩电机**：Menagerie 的 Panda 默认位置伺服，`d.ctrl` 是位置目标。
   力矩级控制必须就地把执行器改为直通电机，否则内置 PD 与外层控制律打架。
2. **Pinocchio 的 armature 双重计入**：`pin.rnea` 与 `pin.crba` 均已包含 armature，
   但 `computeJointTorqueRegressor` 不包含，需在回归矩阵中单独补 `diag(a)` 列。
3. **夹爪耦合污染**：带夹爪模型中把夹爪期望位置设为 0，会通过耦合惯量 `M[:7,7:]`
   向手臂注入虚假力矩。基准改用 `panda_nohand.xml` 消除混淆变量。
4. **"精确模型"并不精确**：MuJoCo 的 `dof_damping = 1.0` 是 Pinocchio 不建模的
   关节粘性阻尼，导致最初的"精确 CTC"反而不如 PD。把摩擦纳入可辨识参数后修复。
5. **自适应增益上界**：Γ 从 0.05 扫到 2.0，Γ=0.5 最优；Γ=2.0 时参数发散触发投影界，
   说明自适应增益并非越大越好。

## 未知负载突变实验（`demos/demo_payload.py`）

上面的基准里 PD 表现很好，容易误导人以为"自适应控制没用"。真实原因是那条轨迹
慢、重力补偿准确，模型误差几乎不起作用。本实验制造工程中最常见的情形：
**t = 8 s 时末端突然挂上 2 kg 未知负载**（控制器完全不知道）。

| 控制器 | 挂载前 5–8s | 冲击 8–10s | 恢复后 15–20s | 精度损失 |
|---|---|---|---|---|
| PD + 重力补偿（固定增益） | 1.49 | 46.88 | 52.83 mrad | **35.4 ×** |
| CTC（模型不含负载） | 1.04 | 28.93 | 28.67 mrad | **27.4 ×** |
| **MBAC（Slotine-Li 自适应）** | 2.43 | 5.78 | **2.39 mrad** | **1.0 ×** |
| **RBF-NN 自适应** | 1.89 | 9.76 | **2.93 mrad** | **1.6 ×** |

结论：**自适应控制的价值不是"标称条件下精度更高"，而是"模型变了还能自己修正"。**
固定增益控制器（无论是 PD 还是精确模型的 CTC）都无法消除未知负载引起的稳态误差；
MBAC 把负载视为末端连杆等效质量的变化，在线重新估计后误差完全回落到原水平。

这也解释了为什么在标称基准中 PD（1.17 mrad）看起来优于 MBAC（2.14 mrad）：
标称条件对固定模型有利，而自适应控制器为了保持在线学习能力，需要保留一定的
自适应带宽，标称精度略有代价。选控制器要看工况，不能只看一条标称曲线。
