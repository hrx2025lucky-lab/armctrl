# tools/verification —— 探针与变异验证脚本

这里放的不是产品代码，而是**做实验和自查用的一次性脚本**。
把它们留在仓库里，是因为本项目最想展示的东西不是「实现了多少算法」，
而是**怎么确认一个结论是真的**。

## 两类脚本

| 前缀 | 干什么 | 例子 |
|---|---|---|
| `probe_*` | **独立复测**：绕开被测实现，用另一条路把同一个量再算一遍 | `probe_kin.py` 量正运动学/雅可比/可操作度；`probe_k50_contact.py` 用接触点雅可比复算约束力矩 |
| `mut_*` / `verify_*` | **变异验证**：把实现（或文档里的数字）逐条改坏，确认测试真的会红 | `mut_e3_creep.py` 改坏抓取蠕变相关实现；`mut_k50_doc.py` 改坏文档里的实测数字 |

## 为什么需要变异验证

一组永远不会红的测试，和没有测试是一回事。

这类"空测试"从代码上完全看不出来。本项目实际抓到过的例子：

- 某条测试叫 `takes_the_minimum_over_contacts`，名字很到位，
  但夹具全场只用一个摩擦系数，于是每个接触的 μ 都一样，
  `min` 和 `max` 恒等——把实现改成 `max`，测试照样全绿。
- 某个读数叫「切换位置跳变」，实际量的却是「每拍最大位移」，
  于是它有个永远消不掉的地板，还顺手把另一个真实 bug 一起藏住了。

两个都是**变异扫描**抓出来的，不是靠读代码。

## 怎么跑

```bash
cd <repo>
export PYTHONPATH=.
export MUJOCO_GL=egl                     # 无显示环境
export MUJOCO_MENAGERIE=/path/to/mujoco_menagerie

python tools/verification/probe_kin.py           # 探针：直接打印测量结果
python tools/verification/mut_e3_creep.py        # 变异：跑一批，报「杀死 / 存活」
python tools/verification/mut_e3_creep.py --only=M01,M05   # 只跑指定变异体
```

⚠️ **变异脚本会临时改写源文件**，跑完在 `finally` 里原样写回。
中途强杀（Ctrl-C 之外的 SIGKILL）有可能留下改动，用 `git diff` 检查一下即可。

## 关于 `mut_*_doc.py`

带 `_doc` 的那几个变异的是 `armctrl_讲解/` 里的**文档数字**，
用来确认「文档里的实测值有测试守着」。
讲义不随公开仓库分发（混了较多个人学习笔记），
所以这几个脚本在 clone 环境下会因为找不到文档而无法运行——这是预期行为。
其余脚本只依赖代码，可以直接跑。

## 输出长什么样

```
批次 E-3 变异验证：9 个变异体
================================================================
M01 ✅ 被杀 —— 场景默认 impratio 偷偷改成 10（旧测试完全抓不住）
       FAIL: test_raising_impratio_meets_the_spec_with_margin
...
================================================================
杀死 9 / 存活 0
```

「存活」有三种，必须分清，否则会要么补一堆没用的测试、要么放过真缺口：

1. **真活口** —— 测试有缺口，要补断言；
2. **等价变异体** —— 在当前约束下行为确实没变（例如两侧摩擦被强制相等时，
   `min` 与 `max` 恒等），要换锚点或换调用方；
3. **扫描范围没覆盖到** —— 假活口，把被改函数的其它调用方也纳入测试集。
