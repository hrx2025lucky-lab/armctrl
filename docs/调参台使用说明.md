## 0. 启动

```bash
cd <仓库根>
./tuner.sh                 # 默认阻抗场景
./tuner.sh --list          # 列出全部 12 个场景
./tuner.sh grasp           # 指定场景
```

`tuner.sh` 会自动找解释器、设好 `PYTHONPATH` 与 `MUJOCO_GL`，端口被占时也会明确提示。
想指定解释器：`ARMCTRL_PYTHON=/path/to/venv/bin/python ./tuner.sh`。

浏览器打开 `http://127.0.0.1:8770/`。左上角下拉切换场景，画面可拖动旋转、滚轮缩放。

**让别的机器打开**：`./tuner.sh impedance --host 0.0.0.0`，
对方访问 `http://<本机IP>:8770/`。
⚠️ 默认只绑 `127.0.0.1` 是有意为之——**服务没有任何认证**，
谁连上都能改参数。演示完就关掉。

### 界面三个区域

| 区域 | 内容 |
|---|---|
| 左栏 | 参数滑块。**橙色说明文字**解释每个参数的物理含义 |
| 中栏 | MuJoCo 实时画面 + 数字读数 + 实时曲线 |
| 右栏 | 该场景在讲什么 |

**读数里橙色的那一项是"理论值"**，由解析式独立算出，不是把实测值抄一遍。
调滑块时，实测和理论应当一起变、且稳态时重合。**对不上就说明有一方错了**——
这正是这个工具最有价值的地方。

## 0.5 原生窗口按键：那些「画面突然变得很奇怪」的时刻

MuJoCo 原生窗口自带一批可视化开关。**按错了不是报错**，再按一次就恢复。

| 键 | 作用 | 按下去像什么 |
|---|---|---|
| `I` | 惯量盒 | 一堆**红色半透明盒子**罩住机械臂，有的比本体还大 |
| `H` | 凸包 | 每个几何体外套一层多面体 |
| `C` / `F` | 接触点 / 接触力 | 接触处冒出小点和箭头 |
| `T` | 透明 | 整机变半透明 |
| `U` | 执行器 | 显示每个关节的驱动状态 |

### ⭐ `I` 那个红盒子到底是什么

它叫**等效惯量盒**：把连杆换成一个**均匀密度的长方体**，
要求这个盒子的**质量**和**三个主惯量**跟真实连杆完全一样。画出来的就是它。

半边长由三式反解（$I_{xx}=\frac{m}{3}(b^2+c^2)$ 等）：

$$
a=\sqrt{\tfrac{3}{2m}(I_{yy}+I_{zz}-I_{xx})},\quad \text{其余轮换}
$$

**为什么盒子比机械臂还大**：真实连杆是空壳，电机和减速器压在两端，
**质量离转轴很远**。实心均匀的盒子要凑出同样大的转动惯量，只能把体积撑大。

本模型实测（Panda）：

| 连杆 | 质量 | 等效盒子半边长 (m) | 最长/最短 |
|---|---|---|---|
| link1 | 4.971 kg | [0.038 0.061 **0.650**] | 17 |
| link2 | 0.647 kg | [**0.002** 0.113 0.362] | **182** |
| link5 | 1.226 kg | [0.012 0.140 0.265] | 21 |

link1 的等效盒子有 **1.3 米长**，而连杆本身远没那么大。

**那几片"纸"**：link2 有一个方向只剩 **2 毫米**，被压成薄片。
因为它的惯量正好卡在**薄板极限** $I_z = I_x + I_y$（垂直轴定理）上。

### ⭐⭐ 顺带一个和参数辨识直接相关的检查

主惯量必须满足**三角不等式** $I_x + I_y \ge I_z$（三个轮换都要）。
违反它意味着**没有任何实体能有这种惯量**——物理上不可实现。

实测本模型 11 根连杆**全部满足**，最紧的是 link2，余量只有 `1.7e-6`（几乎贴边）。

> ⭐ 这条不是摆设：辨识（见 `identification/`）辨出来的惯量参数**必须**过这一关。
> 最小二乘只保证「拟合误差小」，**不保证结果是个真实存在的物体**——
> 这正是「物理一致性约束」要解决的问题。

## 1. 笛卡尔阻抗控制

### 一句话

让机械臂末端表现得像一个**弹簧 + 阻尼器**：推它会让开，松手会弹回。
不是"顶住不动"，也不是"完全不管"。

### 动手实验

| # | 怎么调 | 会看到什么 | 说明什么 |
|---|---|---|---|
| 1 | 刚度 K：500 → 1500 | 实测 Δz 从 −60 mm 变成 −20 mm，理论线同步变 | 稳态偏移 = F/K，与 K 成反比 |
| 2 | 外力 Fz：−30 → −60 | 偏移翻倍 | 同一 K 下，偏移与外力成正比 |
| 3 | **阻尼比 ζ：1.0 → 0.3** | 每次力开关时**冲过头再来回振荡**，但最终停的位置不变 | ζ 只影响过渡过程，不影响稳态 |
| 4 | ζ：1.0 → 2.0 | 不再过冲，但贴上去很慢 | 过阻尼 |
| 5 | 阻尼设计：critical ↔ fixed | 超调量有差别 | 整定时考不考虑任务空间惯量 Λ |

**实测数据**（K=400, Fz=−40 N）：

| ζ | 实测 Δz 范围 | 理论 F/K | 过冲 |
|---|---|---|---|
| 0.30 | −67.34 ~ **+6.83** mm | −60.00 mm | 7.34 mm，且反向弹出 |
| 1.60 | −59.96 ~ −0.13 mm | −60.00 mm | 0.04 mm |

### 原理（从零推）

控制律是（`armctrl/control/impedance.py`）：

```
τ = Jᵀ · [ K·(p_d − p) + D·(ṗ_d − ṗ) ] + 零空间项 + 动力学补偿
```

`J` 是雅可比，把末端的力 / 力矩换算成关节力矩。

**为什么稳态偏移是 F/K**：稳态时末端不动（ṗ = 0, p̈ = 0），机械臂输出的
"弹簧力" `K·(p_d − p)` 必须恰好抵消外力 `F`：

```
K·(p_d − p) + F = 0      ⇒      p − p_d = F / K
```

代入界面默认值 K = 500 N/m、F = −30 N：`Δz = −30/500 = −0.060 m = −60 mm`，
与读数完全一致。**自己动手时把滑块拨到别的值，用计算器算一遍再对读数**——
这一步比看十遍公式管用。

**为什么 ζ 只影响过渡**：把末端在 z 方向的运动看成一个二阶系统

```
Λ·Δz̈  +  D·Δż  +  K·Δz  =  F
```

`Λ` 是**任务空间惯量**（机械臂在末端方向上"感觉起来有多重"，
由 `Λ = (J M⁻¹ Jᵀ)⁻¹` 算出）。

- 令 t → ∞、导数项归零，得 `Δz = F/K`：**只有 K 决定终点**。
- 阻尼比 `ζ = D / (2√(ΛK))`：决定怎么到终点。
  ζ<1 欠阻尼会振荡，ζ=1 临界阻尼最快且不过冲，ζ>1 过阻尼变迟钝。

代码里 `damping_design="critical"` 用 `D = 2ζ·Λ^½·K^½` 反解 D，
所以你调 ζ 实际是在调这个二阶系统的阻尼比。
`"fixed"` 则忽略 Λ，直接用 `D = 2ζ·K^½`——当机械臂在不同构型下 Λ 变化很大时，
这种简化会让实际阻尼比偏离设定值。

> ⚠️ **已知未修问题**：Albu-Schäffer 的正确阻尼设计是
> `D = ζ(Λ^½K^½ + K^½Λ^½)`（对称化）。当前实现用的是 `D = 2ζΛ^½K^½`，
> 在 Home 构型下非对称度约 8.26%，ζ=1 时最低模态的实际阻尼比是 0.912 而不是 1。
> 这是待修的阶段 4。**务必如实说**。

## 2. PD+重力补偿 vs 计算力矩（CTC）

### 一句话

两者差别只有一处：**用不用模型前馈**。

### 动手实验

| # | 怎么调 | 会看到什么 | 说明什么 |
|---|---|---|---|
| 1 | 控制器在 pd_gravity / ctc 之间切，频率 0.8 Hz | CTC 的跟踪误差 RMS 明显更小 | 模型前馈的价值 |
| 2 | 频率 0.8 → 2.0 Hz | PD 的误差涨得比 CTC 快得多 | 越快，惯量与科氏力越重要 |
| 3 | **模型误差 0 → 30%** | CTC 的优势大幅缩水 | 它前馈的是一个**错的**模型 |
| 4 | Kp 400 → 1200（保持 Kd=2√Kp） | 两者误差都下降 | 高增益能掩盖模型误差，但代价是噪声放大、易饱和 |

### 原理

**PD + 重力补偿**

```
τ = Kp·e + Kd·ė + g(q),        e = q_d − q
```

只补重力。惯量耦合 `M(q)q̈`、科氏与离心力 `C(q,q̇)q̇` 全被当成扰动，
靠反馈"事后追"。

**计算力矩（CTC）**

```
τ = M(q)·( q̈_d + Kd·ė + Kp·e ) + C(q,q̇)q̇ + g(q)
```

把整条动力学算出来前馈掉。代入机器人方程 `M q̈ + C q̇ + g = τ` 得

```
ë + Kd·ė + Kp·e = 0
```

**闭环变成每个关节独立的线性二阶系统**，与构型无关。这就是它的全部价值。

于是增益有了明确含义：

```
ωn = √Kp        ζ = Kd / (2√Kp)
```

界面默认 Kp=400、Kd=40 → ωn = 20 rad/s、ζ = 1.0（临界阻尼）。
**调 Kp 时按 `Kd = 2√Kp` 同步调 Kd**，否则阻尼比会跑掉。

**关于"模型误差 30%"**：这里是真的按固定方向扰动全部动力学参数
（质量、惯量、摩擦系数），再用扰动后的参数去算 `M`、`C`、`g`。
**不是简单把力矩乘 0.7** —— 后者不等价，因为力矩缩放不改变各项之间的相对关系。
（一条曾经写错、后来被撤回的旧表述，问题正在于此。）

## 3. 自适应控制：MBAC 与 RBF

### 一句话

控制器一开始**不知道**机器人的动力学参数，靠在线更新自己补上，
而且更新律是从 Lyapunov 稳定性推出来的，不是试出来的。

### 动手实验

| # | 怎么调 | 会看到什么 | 说明什么 |
|---|---|---|---|
| 1 | 控制器选 mbac，看前 10 秒 | 跟踪误差从很大逐步收敛 | 在线辨识起作用了 |
| 2 | 自适应增益 Γ：0.5 → 2.0 | 收敛更快，但太大会抖 | 步长与稳定性的取舍 |
| 3 | **同时看两条曲线** | 跟踪误差掉下去了，**参数偏差可能一直停在高位** | **跟踪收敛 ≠ 参数收敛** |
| 4 | 频率 0.6 → 0.2 Hz，幅值调小 | 参数偏差更难下降 | 激励不足（PE 条件不满足） |
| 5 | 换成 rbf | 误差也能收敛，但参数偏差项显示为空 | RBF 逼近的是函数，没有"真参数"可比 |

### 原理

**MBAC（Slotine-Li）**的关键前提：机器人动力学**严格线性于参数**

```
M(q)q̈ + C(q,q̇)q̇ + g(q)  =  Y(q, q̇, q̇_r, q̈_r) · π
```

`π` 是质量、质心、惯量、摩擦系数等物理参数拼成的向量；
`Y` 是只依赖运动状态、不依赖参数的**回归矩阵**。
（你二自由度论文里手推的 5 参数回归矩阵就是这个东西；
七自由度版本用 Pinocchio 自动生成，再用 SVD 求出 62 维可辨识子空间。）

控制律与更新律：

```
s = ė + λe                    （滑模面：把位置和速度误差合成一个量，e = q_d − q）
τ = Y·π̂ + Kd·s
π̂̇ = +Γ·Yᵀ·s                  （更新律）
```

> ⚠️ 两处**加号**绑死在 `e = q_d − q`、`s = ė + λe`、`π̃ = π̂ − π` 这套约定上，
> 与 `armctrl/control/adaptive.py:115,118` 一致。
> 有的教材用镜像约定 `s = q̇ − q̇_r`，那边两处都是减号，同样正确——**别混用**。

**更新律不是猜的**，是构造 Lyapunov 函数

```
V = ½·sᵀ·M·s  +  ½·π̃ᵀ·Γ⁻¹·π̃          （π̃ = π̂ − π 是参数误差）
```

求导后利用 `Ṁ − 2C` 的**斜对称性**消去一大块，得到

```
V̇ = −sᵀ·Kd·s ≤ 0
```

于是跟踪误差渐近收敛。

> ⚠️ 严格说 `V̇ ≤ 0` 只给出**稳定 + s 有界**，要得到 `s → 0` 还需补 Barbalat 引理
> （再证 `ṡ` 有界 ⇒ `V̇` 一致连续）。完整四步见 `armctrl_讲解/03_自适应控制.md` §六。

> 注意措辞：**斜对称的是 `Ṁ − 2C`**。`Ṁ = C + Cᵀ` 是等价恒等式，
> 但它本身不是"斜对称矩阵"。这个说法说反了，内行一听就知道。

**为什么跟踪收敛不等于参数收敛**：`V̇ = −sᵀKd s` 只保证 `s → 0`。
`s → 0` 时更新律 `π̂̇ = +Γ Yᵀ s → 0`，参数就**停在哪儿算哪儿**。
要让 `π̂ → π`，需要轨迹足够"丰富"，使 `Y` 在时间上张满整个参数空间——
这就是**持续激励（Persistent Excitation, PE）条件**。
实验 4 里把频率和幅值调小，就是在破坏 PE。

**RBF 神经网络自适应**不假设线性于参数，用一组高斯基函数逼近整个动力学。
代价是存在**逼近误差**，所以结论只能到**一致最终有界（UUB）**：
误差进入一个有界邻域并留在里面，而不是趋于零。

**和强化学习的区别**（这个一定要能答）：

| | RBF 自适应 | 强化学习 |
|---|---|---|
| 更新律来源 | Lyapunov 推导 | 试错 + 奖励 |
| 数据需求 | 不需要数据集，在线更新 | 海量采样，通常离线训练 |
| 稳定性 | 可证（UUB） | 无保证 |
| 目标 | 跟踪给定轨迹 | 最大化累计奖励 |

两者都用"神经网络"三个字，但完全不是一回事。

## 4. 动量观测器：不用力传感器估外力

### 一句话

机械臂没有力传感器，靠"电机发了多少力矩"和"实际动成什么样"之间的差
反推外部受力。

### 动手实验

| # | 怎么调 | 会看到什么 | 说明什么 |
|---|---|---|---|
| 1 | 默认参数看几个周期 | 估计 Fz 跟随真实 Fz，但有滞后 | 观测器是一阶低通 |
| 2 | **带宽 K_I：30 → 100** | 检测延迟明显变短，残差变毛躁 | 带宽换延迟，延迟换抗噪 |
| 3 | K_I：30 → 8 | 估计值追不上真实值，延迟大 | 带宽不足 |
| 4 | 阈值调到很低 | 没撞的时候也报警 | 误报 |
| 5 | 检测后反应：none ↔ compliant | compliant 撞到之后会"让开" | 协作机器人的安全策略 |

### 原理

广义动量 `p = M(q)·q̇`。对它求导并代入机器人方程：

```
ṗ = Ṁ q̇ + M q̈ = τ + Cᵀq̇ − g + τ_ext
```

（用到了 `Ṁ = C + Cᵀ`）

如果没有外力，`τ + Cᵀq̇ − g` 应该恰好等于 `ṗ`。对不上的部分就是 `τ_ext`。

直接对 `p` 求导会放大噪声，所以做成积分形式：

```
r = K_I · [ p − p(0) − ∫₀ᵗ ( τ + Cᵀq̇ − g + r ) dt ]
```

可以证明 `r` 与真实外力矩之间是**一阶低通**关系：

```
r(s) / τ_ext(s) = K_I / (s + K_I)
```

所以：
- 时间常数 `1/K_I`。K_I = 30 → 33 ms；K_I = 100 → 10 ms。
- **这就是实验 2 的直接解释**：带宽越高越快，但也把噪声一起放进来了。

再用 `F ≈ (Jᵀ)⁺ · r` 把关节力矩残差映射成末端的笛卡尔力。

> ⚠️ **已知未修问题（阶段 5）**：当前实现有一处**时间错拍**——
> 少了一项 `K_I·Δt·(u_{k−1} − u_k)`；另外没有把 `qfrc_passive`（被动力，
> 如关节阻尼）算进去，导致无外力时也有 RMS 0.5145 N·m 的假残差；
> 纳入后降到 0.000982 N·m。如实说。

## 5. RRT-Connect 路径规划与避障

### 一句话

起点和终点各自都不碰撞，**不代表它们之间的直线不碰撞**——这就是规划存在的理由。

### 动手实验

| # | 怎么调 | 会看到什么 | 说明什么 |
|---|---|---|---|
| 1 | 换**随机种子** | 每次路径完全不同 | 随机采样算法的本质 |
| 2 | **平滑迭代** 300 → 0 | 原始路径明显绕，长度大幅上升 | RRT 不是最优算法 |
| 3 | **安全裕度**调大 | 路径离柱子更远；太大会规划失败 | 裕度与可行性的取舍 |
| 4 | **时间律** scurve ↔ blend_toppra | 停顿 4 次 → 0 次，时长 4.61 s → 3.41 s | 拐角倒圆 + 时间最优 |
| 5 | 倒角偏离预算调大 | 更快，但路径离障碍更近 | 倒角吃掉的是安全余量 |
| 6 | v_max / a_max 调大 | 只改**走多快**，不改**走哪条线** | 几何规划与时间参数化是分开的 |

**实测数据**（seed=0，6 个路径点）：

| 时间律 | 时长 | 中途停顿 | 峰值 jerk | 路径偏离 |
|---|---|---|---|---|
| 逐段 S 曲线 | 4.61 s | 4 次 | 30（有界） | 0 |
| 倒角 + TOPP-RA | **3.41 s** | 0 次 | 851（无界） | 60 mm |

### 原理

**RRT-Connect**：起点和终点各长一棵树，随机撒点让树往自由空间里长，
两棵树接上就通了。

- **概率完备**：有解时，采样数趋于无穷则找到解的概率趋于 1。
  **没有有限步保证**——所以"失败"只能理解为"预算内没找到"，
  **不能**理解为"证明无解"。
- **不最优**：原始路径通常比最短路长 2–3 倍，必须接平滑。

**短路平滑**：在路径上随机取两个点，若它们之间的直线无碰撞且更短，就替换中间那段。
实测能把长度压到原始的 0.32–0.51 倍。

**为什么逐段 S 曲线必须在每个路径点停**：折线在拐角处切线方向是**跳变**的。
路径写成 `q(s) = q_a + u·s`，拐角前后 `u` 不同，于是 `q̇ = u·ṡ` 跳变，
除非 `ṡ = 0`。速度不为零就意味着加速度是冲激，任何有界力矩的机器人都执行不了。

**圆弧倒角**解决这个问题：把拐角换成一段圆弧，切线连续变化。
给定允许偏离 δ 和转角 θ，从拐点沿两侧各退回

```
L = δ · sin(θ/2) / (1 − cos(θ/2)),      半径 r = L / tan(θ/2)
```

（这是我自己推的，推导过程在 `armctrl/planning/blend.py` 的模块文档里。）

**TOPP-RA（时间最优路径参数化）**：路径固定后，机器人的运动只剩一个自由度——
"沿路径走多快"。令 `x = ṡ²`，则关节速度约束 `|q′ẋ| ≤ v` 和加速度约束
对 `(x, s̈)` 都是**线性**的，于是变成一串线性规划，从终点往起点做可达性分析
（Reachability Analysis，名字的来历），再从起点贪心取最大速度。

> ⚠️ **诚实边界**：TOPP-RA 只约束速度和加速度，**不约束 jerk**。
> 最优解必然在若干点上加速度从上界跳到下界（bang-bang），jerk 是冲激。
> 实测峰值 jerk 从 S 曲线的 30 变成 851。
>
> 另外 TOPP-RA 只在离散网格上施加约束，直接求解出来的轨迹实测峰值会
> 超限几个百分点，**且随网格加密并不单调下降**。本实现的做法是
> "求解 → 密采样实测 → 按超限比例降额 → 重解"，直到实测真的达标，
> 并把降额系数如实报出来（典型 0.88–0.94）。

**倒角必须重新做碰撞检测**：圆弧总是往转弯内侧切进去，而障碍常常就在内侧。
原路径无碰撞**不蕴含**倒角后无碰撞。所以规划裕度要比执行裕度大，
多出来的部分正是留给倒角的预算。

## 6. 所有场景共同的诚实边界

这几条要主动说出来，比被追问出来强得多：

1. **MuJoCo 是仿真被控对象，不是真实机器人。** 这里做到的是"实现自洽 +
   数学不变量成立"，**不等于**"算法在真机上正确"。
2. **控制器和被控对象用的是同一套动力学参数，且无噪声、无时延、无摩擦失配。**
   所以跟踪误差数量级（0.08 mrad）不代表真机精度。
3. **碰撞检测是按分辨率采样的**，不是连续保证。采样点之间理论上仍可能钻过
   极薄的障碍物。实测在 0.02 rad 分辨率下，密采样复核的最小间隙比规划裕度
   低约 0.016 mm——这个差额就是离散化的代价。
4. **代码是 AI 辅助编写的。** 诚实说法是："AI 辅助编写，我逐模块读过、
   跑过实验、踩过坑，并引入独立第三方审查找出并修复了自己的 bug。"
5. **仍有未修问题**（阶段 3–7）：阻抗阻尼公式非 Albu-Schäffer、
   动量观测器时间错拍与漏被动力、部分 demo 的指标时间错拍。
   这些会改变已发布的数字口径。
